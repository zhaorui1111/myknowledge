## 1. 企业级研发与运维知识库系统的业务痛点与技术指标

在现代化软件工程实践中，企业知识面临严重的“高碎片化与低流动性”：
1. **线上故障处置慢**：生产环境凌晨突发 Kubernetes Pod 崩溃（CrashLoopBackOff），值班 SRE 必须在海量 Wiki 中搜索相关服务的故障排查手册（Runbook），逐个核对环境变量与数据库慢查询排查步骤，处置黄金时间被严重浪费；
2. **架构规范落地难**：架构委员会发布的《微服务接口幂等性规范》、《分布式事务设计白皮书》长达数百页，业务开发人员往往不通读，写出的代码依然频频出现并发超卖漏洞；
3. **企业严肃场景的严苛指标**：
   * **零幻觉容忍度**：严禁模型脑补捏造根本不存在的数据库配置参数；
   * **100% 精确引用溯源**：每一条技术建议必须明确标注引用自哪一篇内部规范的哪个章节、哪个段落，点击即可直达原文档；
   * **高性能低延迟**：端到端首字响应时间（TTFT）必须控制在 1.5 秒以内。

## 4. 父子文档切分与 PGVector 异步入库管道实现

采用我们前面学到的**父子文档切分（Parent-Document Chunking）**：大文档作为父块提供完整上下文，细粒度切片作为子块用于精准向量召回。

```python
import uuid
import asyncio
from pydantic import BaseModel
from psycopg_pool import AsyncConnectionPool

class KnowledgeParentChunk(BaseModel):
    id: str
    content: str
    service_name: str
    doc_title: str

class KnowledgeChildChunk(BaseModel):
    id: str
    parent_id: str
    content: str
    embedding: list[float]

async def batch_index_devops_docs(
    pool: AsyncConnectionPool,
    parents: list[KnowledgeParentChunk],
    children: list[KnowledgeChildChunk]
):
    """批量异步写入 PostgreSQL 与 PGVector"""
    async with pool.connection() as conn:
        async with conn.cursor() as cur:
            # 1. 批量插入父文档表
            for p in parents:
                await cur.execute(
                    """
                    INSERT INTO devops_parent_documents (id, content, service_name, doc_title)
                    VALUES (%s, %s, %s, %s)
                    ON CONFLICT (id) DO UPDATE SET content = EXCLUDED.content
                    """,
                    (p.id, p.content, p.service_name, p.doc_title)
                )
            
            # 2. 批量插入子切片及向量数据
            for c in children:
                await cur.execute(
                    """
                    INSERT INTO devops_child_chunks (id, parent_id, content, embedding)
                    VALUES (%s, %s, %s, %s::vector)
                    ON CONFLICT (id) DO UPDATE SET embedding = EXCLUDED.embedding
                    """,
                    (c.id, c.parent_id, c.content, str(c.embedding))
                )
        await conn.commit()
    print(f"Successfully indexed {len(parents)} parents and {len(children)} children.")
```

## 5. 混合检索与 Cross-Encoder Reranker 重排序引擎

在 IT 运维中，用户经常查询精准错误码（如 `502 Bad Gateway`、`OOMKilled`、`Error 1045 (28000)`）。纯向量检索在此类场景极易遗漏，必须采用**混合检索 + Cross-Encoder 重排**。

```python
async def hybrid_retrieve_devops_chunks(
    pool: AsyncConnectionPool,
    query_text: str,
    query_vector: list[float],
    service_filter: str | None = None,
    limit: int = 20
) -> list[dict]:
    """SQL 层混合检索：结合 BM25 词频匹配与 PGVector 余弦距离"""
    sql = """
    WITH vector_matches AS (
        SELECT id, parent_id, content,
               1 - (embedding <=> %s::vector) AS dense_score
        FROM devops_child_chunks
        ORDER BY embedding <=> %s::vector ASC
        LIMIT 50
    ),
    keyword_matches AS (
        SELECT id, parent_id, content,
               ts_rank_cd(to_tsvector("simple", content), plainto_tsquery("simple", %s)) AS sparse_score
        FROM devops_child_chunks
        WHERE to_tsvector("simple", content) @@ plainto_tsquery("simple", %s)
        LIMIT 50
    )
    SELECT 
        COALESCE(v.id, k.id) AS id,
        COALESCE(v.parent_id, k.parent_id) AS parent_id,
        COALESCE(v.content, k.content) AS content,
        COALESCE(v.dense_score, 0.0) AS dense_score,
        COALESCE(k.sparse_score, 0.0) AS sparse_score
    FROM vector_matches v
    FULL OUTER JOIN keyword_matches k ON v.id = k.id
    LIMIT %s;
    """
    async with pool.connection() as conn:
        async with conn.cursor() as cur:
            await cur.execute(sql, (str(query_vector), str(query_vector), query_text, query_text, limit))
            rows = await cur.fetchall()
            
    return [{"id": r[0], "parent_id": r[1], "content": r[2], "dense_score": r[3], "sparse_score": r[4]} for r in rows]
```

## 7. 基于 LangGraph 的企业级知识问答状态机全案

我们使用 LangGraph 将整个检索问答流程建模为一个**带自愈与多重校验门禁的有向状态图**：

```
                      [START]
                         │
                         ▼
               [1. QueryRewrite (查询重写)]
                         │
                         ▼
               [2. RetrieveDocs (混合检索)]
                         │
                         ▼
               [3. GradeRelevance (质量评估门禁)]
                         │
             ┌───────────┴───────────┐
             │ 是否有足够相关知识？     │
       [YES] ▼                 [NO]  ▼
[4. GenerateAnswer (生成溯源回答)]   [5. Refusal (严格防幻觉拒答)]
             │                       │
             └───────────┬───────────┘
                         ▼
                       [END]
```

### 7.1 完整端到端手写代码全案

```python
import asyncio
from typing import TypedDict, Annotated, Literal, Any
from langchain_core.messages import BaseMessage, HumanMessage, AIMessage, SystemMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

# 1. 定义全局图状态
class RAGState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]
    original_query: str
    rewritten_query: str
    retrieved_docs: list[dict]
    is_relevant: bool
    final_output: dict[str, Any]

llm = ChatOpenAI(model="gpt-4o", temperature=0.0)

# 2. 节点 1: 查询重写与代词消解 (Query Rewrite)
async def rewrite_query_node(state: RAGState) -> dict[str, Any]:
    query = state["original_query"]
    history = state.get("messages", [])
    
    prompt = (
        "You are an enterprise query optimizer. Based on the conversation history, "
        "rewrite the user latest question into a self-contained, standalone search query. "
        "Eliminate ambiguous pronouns like it, that service, and include technical keywords.

"
        f"Original Question: {query}"
    )
    res = await llm.ainvoke(prompt)
    rewritten = res.content.strip()
    return {"rewritten_query": rewritten}

# 3. 节点 2: 执行混合检索 (Retrieve Docs)
async def retrieve_docs_node(state: RAGState) -> dict[str, Any]:
    query = state["rewritten_query"]
    # 模拟从前文封装的 PGVector 混合检索获取切片并换取父文档
    mock_retrieved = [
        {
            "doc_id": "DOC-K8S-01",
            "doc_title": "Kubernetes 生产集群故障排查标准手册 v4.2",
            "section": "3.2 CrashLoopBackOff 紧急恢复指南",
            "content": "当 Pod 出现 CrashLoopBackOff 时，首先执行 kubectl describe pod 检查终止退出码。若 ExitCode 为 137，代表遭遇操作系统 OOMKilled，必须在 Deployment 中提升 memory limit 并配置 JVM 堆内存比例参数 -XX:MaxRAMPercentage=75.0。"
        }
    ]
    return {"retrieved_docs": mock_retrieved}

# 4. 节点 3: 严格相关性质量评估门禁 (Grade Relevance)
class RelevanceGrade(BaseModel):
    has_sufficient_context: bool = Field(description="文档内容是否足以准确回答用户的问题，无需额外脑补")

async def grade_relevance_node(state: RAGState) -> dict[str, Any]:
    docs_text = "

".join([d["content"] for d in state["retrieved_docs"]])
    prompt = (
        "You are an unbiased technical grader. Evaluate whether the retrieved technical documents "
        "contain factual information to directly answer the user question.

"
        f"Question: {state["rewritten_query"]}

"
        f"Documents:
{docs_text}"
    )
    grader_model = llm.with_structured_output(RelevanceGrade)
    result: RelevanceGrade = await grader_model.ainvoke(prompt)
    return {"is_relevant": result.has_sufficient_context}

# 5. 节点 4: 带有精准引用溯源的回答生成 (Generate Answer)
async def generate_answer_node(state: RAGState) -> dict[str, Any]:
    docs = state["retrieved_docs"]
    formatted_context = ""
    for idx, d in enumerate(docs, start=1):
        formatted_context += f"[{idx}] 来源: 《{d["doc_title"]}》- {d["section"]}
内容: {d["content"]}

"

    system_instruction = (
        "你是一名资深 SRE 架构师。根据提供的企业技术规范回答问题。
"
        "【铁律】:
"
        "1. 必须完全基于提供的上下文回答，严禁推测、捏造未提及的参数或命令；
"
        "2. 在每一个具体结论后，必须严格标注文档出处序号，如 [1]；
"
        "3. 在 citations 数组中结构化列出每一个引用的具体出处与原文摘录。"
    )
    
    prompt = f"参考技术文档:
{formatted_context}

用户问题: {state["rewritten_query"]}"
    
    generator = llm.with_structured_output(GroundedAnswerPayload)
    answer_payload: GroundedAnswerPayload = await generator.ainvoke([
        SystemMessage(content=system_instruction),
        HumanMessage(content=prompt)
    ])
    
    return {
        "final_output": answer_payload.model_dump(),
        "messages": [AIMessage(content=answer_payload.answer_markdown)]
    }

# 6. 节点 5: 严格防幻觉拒答节点 (Refusal)
async def refusal_node(state: RAGState) -> dict[str, Any]:
    refusal_text = (
        "抱歉，在企业内部研发与运维知识库中，未检索到与您问题相关的官方规范或排查手册。
"
        "为了防止误导生产操作，系统已自动阻断回答。建议联系对应微服务维护团队或在内部 SRE 值班群发起人工求助。"
    )
    return {
        "final_output": {"answer_markdown": refusal_text, "citations": []},
        "messages": [AIMessage(content=refusal_text)]
    }

# 7. 条件路由逻辑
def route_after_grading(state: RAGState) -> Literal["generate_answer", "refusal"]:
    if state["is_relevant"]:
        return "generate_answer"
    return "refusal"

# 8. 编译组装状态机
def build_enterprise_rag_graph():
    builder = StateGraph(RAGState)
    
    builder.add_node("rewrite_query", rewrite_query_node)
    builder.add_node("retrieve_docs", retrieve_docs_node)
    builder.add_node("grade_relevance", grade_relevance_node)
    builder.add_node("generate_answer", generate_answer_node)
    builder.add_node("refusal", refusal_node)
    
    builder.add_edge(START, "rewrite_query")
    builder.add_edge("rewrite_query", "retrieve_docs")
    builder.add_edge("retrieve_docs", "grade_relevance")
    
    # 核心质量门禁：只有通过评分才能进入回答生成，否则强制拒答！
    builder.add_conditional_edges(
        "grade_relevance",
        route_after_grading,
        {
            "generate_answer": "generate_answer",
            "refusal": "refusal"
        }
    )
    
    builder.add_edge("generate_answer", END)
    builder.add_edge("refusal", END)
    
    return builder.compile()
```

## 8. 严格拒答与防幻觉护栏（Guardrails）机制

在上述状态机中，**第 4 节的 `grade_relevance` 节点与条件路由构成了一条坚不可摧的“安全护栏”**。
* **传统 RAG 的幻觉漏洞**：传统系统即使检索出来的文档相似度很低（例如检索出了一篇《企业请假管理条例》），依然会硬着头皮把请假条例塞给大模型回答 K8s 崩溃问题，大模型迫于回答压力开始自由编造命令；
* **硬阻断优势**：通过在生成前引入独立的裁判节点，一旦判定上下文与问题不匹配，**执行流直接转向拒答分支，大模型完全没有生成幻觉命令的机会**！

## 9. 多租户与部门级行级安全隔离（Row-Level Security）

在千人企业中，财务系统的敏感拓扑、商业合同等机密技术文档，绝对不能被普通部门人员检索出来。

### 9.1 PostgreSQL 行级安全策略（RLS）实战

```sql
-- 启用表的行级安全
ALTER TABLE devops_child_chunks ENABLE ROW LEVEL SECURITY;

-- 创建基于当前会话租户与部门变量的物理隔离策略
CREATE POLICY department_isolation_policy 
ON devops_child_chunks
FOR SELECT
USING (
    tenant_id = current_setting('app.current_tenant', true)
    AND (
        is_public = true 
        OR allowed_departments @> ARRAY[current_setting('app.current_dept', true)]
    )
);
```

```python
    query: str
    session_id: str

async def sse_event_stream(user_query: str, session_id: str) -> AsyncGenerator[str, None]:
    initial_input = {
        "original_query": user_query,
        "messages": [HumanMessage(content=user_query)]
    }
    config = {"configurable": {"thread_id": session_id}}
    
    # 1. 广播初始化状态
    yield f"event: status\ndata: {json.dumps({"step": "rewriting_query", "message": "正在分析上下文并重写问题..."})}\n\n"
    
    # 2. 异步流式执行状态机
    async for event in rag_app.astream(initial_input, config=config):
        for node_name, state_update in event.items():
            if node_name == "retrieve_docs":
                yield f"event: status\ndata: {json.dumps({"step": "retrieved", "count": len(state_update["retrieved_docs"])})}\n\n"
            elif node_name == "grade_relevance":
                yield f"event: status\ndata: {json.dumps({"step": "graded", "passed": state_update["is_relevant"]})}\n\n"
            elif node_name in ["generate_answer", "refusal"]:
                final_payload = state_update["final_output"]
                answer_text = final_payload["answer_markdown"]
                
                # 3. 模拟打字机流式下发字符
                for char in answer_text:
                    yield f"event: delta\ndata: {json.dumps({"token": char})}\n\n"
                    await asyncio.sleep(0.01)
                    
                # 4. 传输最终的结构化引用元数据，供前端卡片渲染高亮
                yield f"event: citations\ndata: {json.dumps(final_payload.get("citations", []))}\n\n"
                
    yield "event: done\ndata: [DONE]\n\n"

@api.post("/api/v1/devops/chat")
async def chat_devops_endpoint(req: ChatQueryRequest):
    return StreamingResponse(
        sse_event_stream(req.query, req.session_id),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no"
        }
    )
```

```typescript
// 前端 SSE 消费处理示例 (基于 fetch-event-source)
import { fetchEventSource } from "@microsoft/fetch-event-source";

interface CitationItem {
  citation_id: number;
  doc_id: string;
  doc_title: string;
  section_title: string;
  exact_quote: string;
}

export function connectDevOpsAssistant(
  query: string,
  sessionId: string,
  onToken: (token: string) => void,
  onStatus: (step: string) => void,
  onCitations: (citations: CitationItem[]) => void
) {
  fetchEventSource("/api/v1/devops/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ query, session_id: sessionId }),
    onmessage(ev) {
      if (ev.event === "delta") {
        const data = JSON.parse(ev.data);
        onToken(data.token);
      } else if (ev.event === "status") {
        const data = JSON.parse(ev.data);
        onStatus(data.message || data.step);
      } else if (ev.event === "citations") {
        const citations: CitationItem[] = JSON.parse(ev.data);
        onCitations(citations); // 渲染底部“参考文档”卡片与点击高亮抽屉
      }
    }
  });
```

## 15. 生产环境避坑指南

### 坑一：虚构引用标号（Hallucinated Citation Footnotes）
* **现象**：大模型在生成的 Markdown 正文中煞有介事地标注了 `[1]`, `[2]`, `[3]`，但在结构化的 `citations` 数组中却只有 1 个条目，导致前端用户点击 `[3]` 抛出越界异常。
* **正解**：在 `generate_answer_node` 后置一个轻量级校验断言，使用正则 `re.findall(r"\[(\d+)\]", answer)` 提取正文全部标号，与 `citations` 对象的 `citation_id` 集合做对称差集校验，若不一致立即在代码层自动清洗剔除悬空标号。

### 坑二：技术文档中的超长代码块跨切片被生硬斩断
* **现象**：一段 200 行的 Ansible 部署脚本或 Nginx 配置，被切片器从第 50 行硬切断，后半截缺失了开头大括号，检索出来交给模型时引发语法误导。
* **正解**：在代码块处理时采用专门的“语言感知切片器（Language-Aware Splitter）”，强制以函数定义或配置块（Block）为最小原子单元，绝对禁止将单个函数截成两半。

```
企业知识库问答助手生产级全景闭环：
├── 1. 结构化输入：技术文档入库必须保留代码块完整性，注入 service_name 等丰富元数据

├── 4. 溯源高于一切：每条结论强制绑定精确引用序号 [1] 与结构化 Citation 实体，让工程师敢信敢用
└── 5. 极致交互交付：基于 FastAPI + SSE 打造打字机流式推流，无缝对接前后端事件帧协议与监控大盘
```
